# Hakrawler performance research — 2026-11-23

**Status:** research only. The crawler source is unchanged on this branch — it is a
base for future tests. No production systems were touched during this work.

**Tracking:** internal backlog item `HAKRAWLER-PERF-2026-11-23`. Internal context is
deliberately kept out of this public repository; this document contains only
information about the crawler itself and a local, synthetic benchmark.

## Method

- Built this repo's `master` with Go 1.27 and compared it against local prototypes.
- Traffic generated by `bench/server.py` on loopback, with a configurable response
  delay (30 ms used below) — synthetic, not a real-world site.
- Each scenario run 2–3 times; output equivalence checked with `diff`.

## Findings

### 1. Empty `PROXY` URL silently disables crawling

```go
proxyURL, _ := url.Parse(os.Getenv("PROXY"))   // "" -> non-nil *url.URL
if proxyURL != nil { transport.Proxy = http.ProxyURL(proxyURL) }
```

`url.Parse("")` returns a non-nil, empty URL, so the shared transport gets an
invalid proxy and **every request fails without an error being logged**. This is
why an earlier performance attempt (shared transport) appeared to break crawling
and was reverted. Guard with `proxyURL != nil && proxyURL.Host != ""`.

### 2. A new collector and transport per input URL

Each stdin line creates a fresh `colly.Collector` and a fresh `http.Transport`,
discarding keep-alive, TLS session and DNS state between URLs. Sharing one
transport across collectors (with the proxy guard above) gave:

| Scenario (8 threads) | master | shared transport |
|---|---|---|
| 100 URLs, depth 1 | 1.06 s, 101 TCP connections | 0.41 s (**2.6×**), 9 connections |
| 40 URLs, depth 2 | 0.38–1.31 s (erratic), ~120 connections | 0.34–0.37 s (stable), 23 connections |
| Peak RSS | ~17.3 MB | ~16.2 MB |

Output was identical in every case. Fewer connections also means less load on
target servers. Adding dial/TLS/response-header timeouts and `ForceAttemptHTTP2`
to the shared transport is safe; HTTP/2 was not exercised by the plain-HTTP
benchmark, so its benefit applies to HTTPS targets only.

Side effect: this also fixes `-proxy`, which is currently ignored (a crawl with a
dead proxy still returns results).

### 3. No deduplication between input URLs

Each collector has its own visited set, so overlapping inputs refetch the same
pages. A shared visited set (`Request.Abort()` on duplicates) reduced a same-host
overlapping crawl from 160 → 47 HTTP requests and 0.35 s → 0.19 s, with identical
unique output. Caveats: without `-u` fewer duplicate lines are emitted, and
colly's scope/filter-vs-callback ordering should be verified before relying on it.

### 4. `-t` is applied twice

`-t` is both the number of worker goroutines and the per-collector colly
`Parallelism`, so in-flight requests can reach **t²** (64 by default, 10,000 at
`-t 100`). This is a likely contributor to resource exhaustion at high thread
counts. A global semaphore or decoupled flags would cap it.

### 5. `-timeout` does not cancel the crawl

On timeout the worker moves on, but the crawl goroutine keeps running and can
hold connections. colly v2.2.0 adds `Context` support, which enables real
cancellation.

### 6. Dependency age

colly is pinned to a 2022 pseudo-version. Upgrading to v2.2.0 works after the
proxy fix, produces identical results (different ordering only), and brings
bug/data-race fixes — no direct speed gain was measured.

## Suggested order of work

1. Guard the proxy URL, share one transport, add timeouts/HTTP2 (low risk, measured win).
2. Cap effective concurrency (avoid t²).
3. Add cross-input dedup (verify scope semantics first).
4. Upgrade colly and use its Context support for real timeout cancellation.
5. Consider a bounded set or external `sort -u` for `-u` on very long runs.

## Reproducing

```sh
python3 bench/server.py                      # terminal 1
curl -s http://127.0.0.1:8899/__reset
seq 0 99 | sed 's|^|http://127.0.0.1:8899/p/|' | ./hakrawler -d 1 -t 8 > /dev/null
curl -s http://127.0.0.1:8899/__stats        # {"requests": ..., "connections": ...}
```

Server options: `BENCH_PORT`, `BENCH_LINKS`, `BENCH_DELAY`, `BENCH_PAGES`.
Enable `TCP_NODELAY` on any test server — without it, keep-alive connections show
an artificial delayed-ACK penalty that makes connection reuse look slower than it is.
